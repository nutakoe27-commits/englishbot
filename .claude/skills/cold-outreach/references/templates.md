# Шаблоны артефактов

Для режима C. Каждый шаблон — структура плюс правило заполнения. Правила важнее структуры: заполненная по форме, но выдуманная по содержанию таблица хуже, чем её отсутствие, потому что ею начнут пользоваться.

---

## 1. Карта ценности

Базовый артефакт: из него потом берутся меню выгод для гипотезы, аргументация в презентации и поводы для касаний в дожиме. Делается один раз на продукт, обновляется раз в полгода.

| Роль | Ключевая ценность | Желаемое будущее | За счёт чего мы это обеспечим |
|---|---|---|---|
| Директор частной школы | Удержание учеников | Ученики не уходят через 2 месяца, родители видят прогресс | Кабинет преподавателя показывает динамику по каждому ученику, есть что показать родителю |
| Завуч госшколы | Отсутствие риска | Отчётность закрыта, проверка прошла спокойно | Выгрузка в Excel по всем ученикам за месяц одной кнопкой |
| … | … | … | … |

**Правила заполнения:**

- «Желаемое будущее» пишется **словами клиента**, а не маркетинговыми. Не «повышение вовлечённости», а «дети перестали молчать на уроке».
- Колонка «за счёт чего» обязательна и заполняется последней. Если её нечем заполнить — выгода выдумана, строку надо убрать.
- Не больше 3–4 ценностей на роль. Длинный список означает, что главная не найдена.
- Самый надёжный способ наполнить карту — спросить действующих клиентов прямым текстом: «за что вы нам платите?». Ответы почти никогда не совпадают с тем, что вы считали своей ценностью.

## 2. Банк вопросов

Минимум восемь вопросов, сгруппированных по типам. Однотипные вопросы про размер и объёмы не включать — они интересны только менеджеру и вызывают у клиента изжогу.

```
## Квалифицирующие (кто передо мной)
1. …

## О сути (как устроено сейчас)
2. …
3. …

## О происхождении (как пришли к текущему)
4. …
5. …

## О желаемом будущем
6. …
7. …

## Субъективные (отношение)
8. …

## Проясняющие (для размытых формулировок)
— «А что в вашем понимании …?»
```

**Правила:**

- Первые три вопроса помечаются как стартовый блок — они уходят одним сообщением, не по одному.
- Перед блоком всегда идёт вход в воронку («задам несколько вопросов, чтобы понять…»). Без него вопросы превращаются в допрос.
- Лучшие вопросы начинаются на «как», «какой», «какие», «куда», «кому». Вопросов «почему» в банке быть не должно — они звучат как претензия.

## 3. Ответы на возражения

8–12 типовых возражений. Формат каждого:

```
### «[возражение дословно, как его говорят клиенты]»

**Что за этим обычно стоит:** …
**Стадия:** первичное сопротивление / истинное сомнение после цены
**Техника:** согласие / реверс / фокус / Марк Аврелий / разложение
**Формулировка:**
> …
**Дальше:** какой следующий шаг предложить (закрытие всегда следует за отработкой)
```

**Правила:**

- Обязательно различать стадию. «Дорого» до презентации и «дорого» после цены — два разных возражения с разными техниками. Первое лечится доверием, второе — разложением на три причины.
- Возражения собираются из реальных диалогов, а не придумываются. Если базы диалогов нет, так и скажи — и предложи начать с десяти самых частых по памяти менеджеров, пометив их как гипотезы.
- Каждый ответ заканчивается движением вперёд, а не точкой.

## 4. Пакетные предложения

Три-четыре пакета, не больше и не меньше. Выстраиваются на контрасте: первый заведомо невыгодный для клиента, он вводит систему сравнения; второй тоже не идеальный, показывает движение навстречу; третий — целевой, к которому ведём.

| | Пакет 1 (якорь) | Пакет 2 | Пакет 3 (целевой) |
|---|---|---|---|
| Цена | самая высокая | | |
| Кому | | | |
| Входит | | | |
| Не входит | | | |
| Ограничение | | | |

**Правила:**

- Опции должны быть настоящими и ценными. Классический антипример: в VIP-пакет включили «фото со спикером», хотя сфотографироваться мог любой — ценность всего пакета от этого упала.
- Презентовать сверху вниз, от дорогого к дешёвому. На фоне 100 тысяч 80 не кажутся большими; в обратном порядке 100 кажутся переплатой.
- Ограничения в пакетах должны быть исполнимыми. Если написано «15 мест» — их должно быть 15.
- Пересчитать юнит-экономику по каждому пакету перед публикацией.

## 5. Реанимационные формулировки

8–10 фраз, разложенных по нарастанию прямоты, чтобы менеджер мог идти по ним от касания к касанию, а не повторять одно и то же.

| # | Ситуация | Формулировка | Когда применять |
|---|---|---|---|
| 1 | Первое напоминание | Констатация, на чём остановились | Через 2–3 дня |
| 2 | Второе | «Удалось посмотреть …?» | Через неделю |
| 3 | Третье | Имя со знаком вопроса | Через 3–4 дня после второго |
| … | | | |

**Правила:**

- Готовых фраз в `methods.md` → «Реанимация» девять штук. Задача при сборке артефакта — адаптировать их под продукт и расставить по порядку, а не переписать заново.
- Формулировка №9 («понимаю, что выгляжу настойчивым… 10 марта вы говорили: [цитата]») требует сохранённых дословных цитат клиента. Если CRM их не хранит, приём недоступен — отметь это явно, иначе менеджер будет цитировать по памяти и ошибётся.
- Предел — 3–5 касаний. После них — не новая формулировка, а ревизия своих ошибок на предыдущих этапах.

---

## Общее правило по всем артефактам

Артефакт, который некому поддерживать, умирает за месяц. При выдаче любого артефакта добавляй одну строку: **кто его владелец и как часто он обновляется**. Это дешевле, чем через полгода обнаружить, что менеджеры пользуются устаревшим прайсом.
