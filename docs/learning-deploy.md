# Учебная программа: деплой на тестовый сервис

Если миграции 0001–0043 уже применены, обновление с готовыми учебными
модулями и разделёнными квотами устанавливается по
[короткой инструкции](learning-modules-deploy.md): добавляется 0044.
Исторические миграции повторять не требуется. Выход в прод описан в
[learning-production-release.md](learning-production-release.md).

Обновление добавляет связанные уроки A1–C1, бесконечные циклы практики,
сохранение этапов, диагностику после каждых 20 завершённых уроков, маршрут,
карту навыков и просмотр программы ученика в админке.
Для фоновых работников используется MySQL 8 с поддержкой `SKIP LOCKED`.

Функция включается серверной переменной `LEARNING_ENABLED=true`.
По умолчанию она выключена. GitHub Actions остаётся отключённым.
Новый код опубликован в `main`; запуск тестового сервиса выполняется вручную.

## 1. Получить код в папке тестового сервиса

Ниже нужно подставить путь к вашему тестовому checkout, текущее имя
Compose-проекта тестового сервиса, имя тестовой базы и пользователя.

```bash
cd /ПУТЬ/К/ТЕСТОВОМУ/englishbot
git pull --ff-only origin main

TEST_PROJECT='ВСТАВЬ_ИМЯ_COMPOSE_ПРОЕКТА_ТЕСТА'
TEST_DB_NAME='ВСТАВЬ_ИМЯ_ТЕСТОВОЙ_БАЗЫ'
TEST_DB_USER='ВСТАВЬ_ПОЛЬЗОВАТЕЛЯ_ТЕСТОВОЙ_БАЗЫ'
```

Узнать текущий Compose-проект можно командой `docker compose ls`.
Для новой отдельной установки подходит имя `englishbot-test`.
Все команды ниже выполнять в той же shell-сессии.

## 2. Заполнить `.env` тестового сервиса

Compose использует `.env` в текущей папке и передаёт его backend.
В нём должны быть актуальные значения тестовой среды:

```ini
DATABASE_URL=mysql+asyncmy://ВСТАВЬ_ПОЛЬЗОВАТЕЛЯ:ВСТАВЬ_URL_ENCODED_ПАРОЛЬ@host.docker.internal:3306/ВСТАВЬ_ИМЯ_БАЗЫ?charset=utf8mb4

LEARNING_ENABLED=true
LEARNING_MEDIA_DIR=data/learning

BACKEND_PORT=9082
MINIAPP_PORT=9081
ADMIN_PORT=9083

MINIAPP_URL=https://ВСТАВЬ_ДОМЕН_ТЕСТОВОГО_ПРИЛОЖЕНИЯ
ADMIN_HOST=ВСТАВЬ_ДОМЕН_ТЕСТОВОЙ_АДМИНКИ
API_PUBLIC_URL=https://ВСТАВЬ_ДОМЕН_ТЕСТОВОГО_API
VITE_API_BASE=https://ВСТАВЬ_ДОМЕН_ТЕСТОВОГО_API

YOOKASSA_RECURRING_ENABLED=false
MYTRACKER_APP_ID=
MYTRACKER_S2S_TOKEN=
VITE_MYTRACKER_ID=
```

Порты 9081/9082/9083 — пример принятых staging-портов; если тестовый сервис
уже использует другие, сохранить его значения и соответствующий Nginx.
Для Docker адрес MySQL выше подходит при размещении базы на хосте.
Сохранить ваш рабочий адрес базы, если он другой. Имя базы и пользователь
должны совпадать с `TEST_DB_NAME` и `TEST_DB_USER` из первого шага.
Специальные символы пароля в URL должны быть percent-encoded.

Сохранить существующие тестовые `AUTH_JWT_SECRET`, `ADMIN_TOKEN`, настройки
входа и GPU-сервисов `VLLM_BASE_URL`, `VLLM_MODEL_NAME`, `WHISPER_STT_URL`,
`KOKORO_TTS_URL`. Без GPU-сервисов доступны готовые задания и текстовый
разговор, но нет озвучки, распознавания голоса и персональной AI-проверки.

MyTracker для этого тестирования выключен, чтобы события тестового сервиса
не отправлялись в рабочий рекламный счётчик. Для проверки мобильной
аналитики использовать отдельное тестовое приложение MyTracker и его ключ.

## 3. Собрать новые образы, пока существующий сервис продолжает работать

```bash
docker compose -p "$TEST_PROJECT" build backend miniapp admin
```

Это только сборка. Новый backend пока не запускается: сначала нужно
дополнить схему базы. Для помощника миграций нужен именно новый образ,
поскольку он проверяет схему по актуальным моделям приложения.

## 4. Проверить имеющиеся миграции

```bash
docker compose -p "$TEST_PROJECT" run --rm -T --no-deps \
  --entrypoint python \
  -v "$PWD/db/migrations:/migrations:ro" \
  -v "$PWD/scripts/migrate_database.py:/tmp/migrate_database.py:ro" \
  backend /tmp/migrate_database.py \
  --directory /migrations \
  --expected-database "$TEST_DB_NAME" \
  --expected-user "$TEST_DB_USER"
```

Команда читает `DATABASE_URL` из окружения контейнера, сверяет базу и
пользователя и печатает **Applied versions** и **Missing migrations**.
Без `--apply` она ничего не изменяет. Пароль и полный URL не выводятся.

Помощник работает со всеми файлами 0001–0044, а не только с новой миграцией.
Он поддерживает пустую базу, пропуски в `schema_version` и скопированную
схему без истории миграций.

## 5. Применить недостающие миграции

На время изменения схемы остановить backend именно тестового проекта:

```bash
docker compose -p "$TEST_PROJECT" stop backend

docker compose -p "$TEST_PROJECT" run --rm -T --no-deps \
  --entrypoint python \
  -v "$PWD/db/migrations:/migrations:ro" \
  -v "$PWD/scripts/migrate_database.py:/tmp/migrate_database.py:ro" \
  backend /tmp/migrate_database.py \
  --directory /migrations \
  --expected-database "$TEST_DB_NAME" \
  --expected-user "$TEST_DB_USER" \
  --apply
```

Ожидаемый итог:

```text
Current application tables, columns and ENUM values verified
All migration versions verified
```

Помощник пропускает записанные версии и применяет отсутствующие по порядку.
При восстановлении истории он сохраняет существующие настройки и значения
ENUM из более поздних миграций. Старые удаления аккаунтов Google/Apple и
удаление VK из ENUM не повторяются; добавляются нужные новой версии поля.
Сохранённые legacy identities доступны для чтения, новые способы входа
по-прежнему ограничены поддерживаемыми провайдерами.

Для выполнения нужны права `CREATE`, `ALTER`, `INDEX`, `SELECT`, `UPDATE`,
`INSERT`. DDL в MySQL может коммититься отдельно: при ошибке не запускать
новый backend, устранить указанную причину и повторить помощник. Повторный
успешный запуск не пересоздаёт уроки, аккаунты и результаты.

Если версия уже записана, но её столбцы или обязательные индексы отсутствуют,
финальная проверка остановит деплой с названием проблемы. Такая повреждённая
схема требует отдельного восстановления, вместо ложного сообщения об успехе.

## 6. Запустить тестовый сервис

```bash
docker compose -p "$TEST_PROJECT" up -d backend miniapp admin
docker compose -p "$TEST_PROJECT" ps backend miniapp admin
curl -fsS http://127.0.0.1:9082/health
docker compose -p "$TEST_PROJECT" logs --tail=100 backend
```

Использовать настроенный `BACKEND_PORT` вместо 9082, если он другой.
В логах не должно быть ошибок отсутствующих таблиц или
`[learning] preparation failed`. Озвучка хранится в `./data/learning`,
этот каталог подключён к backend и сохраняется при пересборке.

Действующий Nginx тестового сервиса должен проксировать API на его backend
порт, miniapp — на его miniapp порт, admin — на его admin порт.
AI-реплика ограничена 25 секундами, озвучка и распознавание — 40 секундами.
Для `/api/learning/` рекомендуется отдельный таймаут 120 секунд с запасом
на сеть и конкурирующие запросы. В HTTPS-блок API добавить:

```nginx
location /api/learning/ {
    proxy_pass http://127.0.0.1:9082;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 10s;
    proxy_read_timeout 120s;
    proxy_send_timeout 120s;
}
```

Подставить ваш тестовый `BACKEND_PORT` вместо 9082.
Для существующей `/api/grammar/` применить настройку 300 секунд из
[предыдущей инструкции](grammar-deploy.md), если на тесте её ещё нет.
После изменения конфигурации:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

Пересборка APK для новой программы не требуется.

## 7. Приёмка

1. Перезагрузить тестовое приложение, пройти тест уровня и нажать
   «Составить мою программу». A1 должен оставаться A1.
2. Выбрать цель; проверить маршрут из 20 уроков и кнопку старта.
3. Пройти все шесть этапов первого урока. Проверить готовые задания,
   аудио, текстовый запасной вариант, разговор и сохранение итога.
4. Выйти посреди урока и вернуться. Должны сохраниться этап, ответы,
   диалог и материалы. Проверить также перезапуск backend.
5. Завершить 20 уроков: появляется диагностика, затем цикл с уроком 21.
   Отмена, повтор ответа и повтор сохранения не увеличивают счётчик.
6. Проверить карту навыков и карточку ученика в админке. Без голосовых
   ответов устная речь остаётся «пока не оценено». Чтение текста вместо
   аудио не считается успешным аудированием.
7. С рабочими GPU-сервисами проверить записанный голос, распознавание,
   персональную обратную связь и новые варианты материалов.

Диагностика использует отдельный банк из 175 заданий, выбирает вопросы
грамматики/лексики по уровням и избегает последних вариантов. Дополнительно
проверяется аудирование и предлагается устная задача. Итоговый CEFR по
учебному тесту основан на грамматике и лексике; слух и устная речь показаны
отдельно. Голосовая оценка AI относится к расшифровке, произношение не оценивается.

## Откат тестового интерфейса

Для возврата к свободным режимам поставить `LEARNING_ENABLED=false` в
тестовом `.env` и пересоздать backend:

```bash
docker compose -p "$TEST_PROJECT" up -d --force-recreate backend
```

Уроки и результаты остаются в базе и доступны после повторного включения.
Схему 0001–0044 для такого отключения откатывать не требуется.
