# Доступ к занятиям и подписка на неделю за 1 ₽

Все уроки и самостоятельные тренажёры требуют действующей личной подписки или доступа школы. Новый пользователь может определить уровень и оформить неделю за 1 ₽. После окончания подписки прогресс сохраняется, а продолжить начатый урок можно после восстановления доступа. Ранее оплаченные и подарочные периоды действуют до своей даты окончания.

Старые настройки `FREE_PERIOD`, `FREE_TRIAL_DAYS` и дневные квоты больше не открывают занятия.

## Два окна

1. После знакомства с приложением пользователь может получить предложение недели за 1 ₽.
   Попытка открыть урок или самостоятельный тренажёр также показывает предложение.
   Кнопка сразу создаёт платёж ЮKassa без выбора тарифа и промокода.
   Если нужен email для чека, поле появляется внутри этого же окна.
2. «Спасибо, не надо» открывает существующий опрос с восемью фиксированными
   ответами, без ввода текста. Сохранение ответа закрывает окно.

Кнопка подписки в профиле открывает полный список доступных тарифов, даже
если подписки ещё нет: 7 дней за 1 ₽, месяц, год и два года. Выбор любой
карточки ведёт сразу к оплате. Неделя за 1 ₽ сохраняет однократность,
автопродление и согласованную цену уже начатой оплаты; промокоды к ней
не применяются. После использования первого предложения остаются обычные
тарифы. Закрытие списка не возвращает ранее закрытое всплывающее окно.

Галочки согласия нет. Есть ссылка «Ознакомиться с офертой». Под кнопкой
показаны первая цена, точная сумма последующих списаний каждые 30 дней и
отмена в профиле. Нажатие кнопки подключения подтверждает показанные условия;
сервер сохраняет время и сумму согласованных условий вместе с платежом.

Оба окна закрываются без ответа. Автоматическое предложение при следующем
входе возможно максимум раз в 24 часа после знакомства с приложением; после ответа
оно больше не появляется. Явная попытка открыть платный инструмент всё равно
показывает оплату, но повторно опрашивать уже ответившего пользователя не будет.

SALE20 и OLD50 отключаются миграцией и отвергаются платёжным API даже при
случайном включении администратором. Старая рассылка этих промокодов отключена.
Остальные промокоды и обычные тарифы существующих подписчиков сохраняются;
к неделе за 1 ₽ промокоды не применяются.

## Оплата и продление

Переиспользуется `trial7`: строго 1 ₽ и 7 дней независимо от старого
`SUBSCRIPTION_PRICE_TRIAL7_RUB`. Доступно только до первой успешной личной
покупки, включая возвращённые покупки. Ранее купленная пробная неделя тоже
считается использованной. Повторно оплатить 1 ₽ нельзя; вернувшемуся бывшему
подписчику предлагается месячный доступ по обычной цене.

Автоплатежи ЮKassa обязательны. Нужны `YOOKASSA_RECURRING_ENABLED=true`,
рабочие ключи магазина и подключённые автоплатежи банковской картой в ЮKassa.
При недоступном автопродлении предложение нельзя оплатить как разовую неделю.
Это намеренно отличается от старого резервного сценария обычных тарифов.

Сумма первого месячного продления берётся из `SUBSCRIPTION_PRICE_MONTHLY_RUB`
и сохраняется при оформлении. Старые подписки не переоцениваются. Первое
списание по новому предложению — не раньше конца полных 7 дней, последующие —
через 30 дней. Напоминания, отмена и отвязка карты используют существующий
механизм подписок. Изменение настроек цены не меняет уже согласованную сумму.

Один аккаунт резервирует один незавершённый платёж пробной недели. Повторы
используют его же ссылку и неизменный ключ идемпотентности ЮKassa. Сетевой сбой
не считается подтверждённой отменой. Если неизвестный результат остался без
ID провайдера больше 23 часов, API возвращает `payment_pending`: администратор
должен сверить платёж в ЮKassa по metadata.payment_id перед отменой локальной
записи. Не создавать замену вслепую: старый запрос мог быть принят провайдером.

Дублирующий webhook не продлевает доступ повторно и не включает отменённое
автопродление. В тестах запросы к ЮKassa и AI подменяются; реальные деньги
при автоматической проверке не списываются.

## Аналитика

На главном экране админки LTV платного подписчика равен сумме успешных
положительных личных оплат за подписки за всё время, делённой на число
уникальных плательщиков. Неделя за 1 ₽ и продления входят в расчёт.
Возвращённые платежи и школьные счета исключаются. При отсутствии плательщиков
показывается прочерк.

В списке пользователей фильтр учитывает текущий личный и школьный доступ.
Флаг автопродления показывает наличие действующего личного автоплатежа
с привязанным способом оплаты. После отмены автоплатежа флаг выключается
сразу, а доступ сохраняется до конца оплаченного срока.

Вкладка админки «Опрос подписки» показывает новую кампанию `intro_week`:
показы, открытия оплаты, ответы, причины, первые оплаты за 1 ₽ и их выручку.
Ежемесячные продления и старые оплаты со скидками не смешиваются с этой
воронкой. Платёж учитывается при успешном статусе и создании после показа.
Показ означает выдачу окна сервером, а не доказательство просмотра.
История старой кампании и уже сохранённые ответы остаются в MySQL.

## Ручной деплой

Для изменения доступа и LTV новых SQL-миграций нет. На базе с версиями 1–46 достаточно обновить образы. Инструкция SQL ниже предназначена для перехода с версии 45 на 46. Если
история отличается, сначала восстановить пропуски по
[learning-production-release.md](learning-production-release.md).

```bash
cd /ПУТЬ/К/englishbot
git pull --ff-only origin main
docker compose ls
PROD_PROJECT='ИМЯ_СУЩЕСТВУЮЩЕГО_COMPOSE_ПРОЕКТА'
docker compose -p "$PROD_PROJECT" build backend miniapp admin
```

До переключения обновить существующие значения в `.env` (не создавать
дубли строк). Ключи ЮKassa не менять:

```dotenv
LEARNING_ENABLED=true
FREE_PERIOD=false
FREE_TRIAL_DAYS=0
YOOKASSA_RECURRING_ENABLED=true
# SUBSCRIPTION_PRICE_MONTHLY_RUB — оставить согласованную месячную цену.
```

SQL выполнять напрямую на хосте, без Docker. Для продакшена подтверждены
имя базы и пользователь `megotim4y2`. Для другого сервиса заменить оба:

```bash
APP_DB='megotim4y2'
APP_DB_USER='megotim4y2'
umask 077
mkdir -p backups
mysqldump --single-transaction --no-tablespaces -u "$APP_DB_USER" -p "$APP_DB" > "backups/before-intro-lesson-$(date +%Y%m%d-%H%M%S).sql"
```

После успешного создания резервной копии:

```bash
mysql -u "$APP_DB_USER" -p "$APP_DB" < db/migrations/0046_intro_lesson_subscription.sql
mysql -u "$APP_DB_USER" -p "$APP_DB" -e "SELECT version FROM schema_version WHERE version=46; SHOW COLUMNS FROM payments LIKE 'checkout_data'; SHOW COLUMNS FROM recurring_subscriptions WHERE Field IN ('charge_before_hours','setup_payment_id'); SHOW COLUMNS FROM subscription_offer_impressions LIKE 'campaign'; SELECT code,active FROM promo_codes WHERE code IN ('SALE20','OLD50');"
```

Ожидаются версия 46, все четыре новые колонки и `active=0` у обеих скидок.
Миграция допускает повторный запуск, не удаляет оплаты, подписки или ответы.
Пересоздать приложения на основном сервере:

```bash
docker compose -p "$PROD_PROJECT" up -d backend miniapp admin
docker compose -p "$PROD_PROJECT" ps
docker compose -p "$PROD_PROJECT" logs --tail=100 backend
```

Бот по текущей конфигурации работает на отдельном сервере. Обновить его там
через существующий Compose-проект и `docker-compose.bot.yml`; не запускать
вторую копию на основном сервере. См. [bot-abroad.md](bot-abroad.md).

Проверить новым аккаунтом: предложение до первого урока и при открытии отдельного тренажёра; отказ → ответ → закрытие; повторный вход без
опроса; доступ действующего подписчика; вкладку аналитики. Отдельно провести
контрольную оплату за 1 ₽ на своём аккаунте и отменить автопродление в профиле,
если не нужен следующий платёж. После успешного webhook в БД:

```sql
-- Подставить ID своего контрольного аккаунта.
SET @test_user_id = 123;
SELECT id,plan,status,amount_rub,days_granted,created_at
FROM payments WHERE user_id=@test_user_id ORDER BY id DESC LIMIT 5;
SELECT subscription_until FROM users WHERE id=@test_user_id;
SELECT status,plan,amount_rub,period_days,next_charge_at,charge_before_hours,setup_payment_id
FROM recurring_subscriptions WHERE user_id=@test_user_id;
SELECT campaign,audience,shown_at,clicked_at FROM subscription_offer_impressions
WHERE user_id=@test_user_id ORDER BY shown_at DESC LIMIT 5;
SELECT reason_code,answered_at FROM subscription_offer_state WHERE user_id=@test_user_id;
```

У первой оплаты: `trial7`, `succeeded`, 1 ₽, 7 дней. У автопродления до отмены:
`active`, `monthly`, согласованная месячная сумма, 30 дней,
`charge_before_hours=0`; `next_charge_at` равен концу оплаченной недели.
После отмены: `canceled`, доступ сохраняется до `subscription_until`.

В карточке акции RuStore указывать неделю за 1 ₽ и условия последующего продления.

## Откат

Не удалять новые колонки и таблицы: они сохраняют историю согласованных
платежей. Старый backend не учитывает новую дату списания и защиту от
дублирующего webhook. Если уже появились оплаты за 1 ₽, перед техническим
откатом временно выключить `YOOKASSA_RECURRING_ENABLED`, затем восстановить
исправленную версию до следующего списания. Не оставлять старый планировщик
работать с новыми подписками. Обычный откат мини-аппа не отменяет подписки.

```bash
TEST_DATABASE_URL='mysql+asyncmy://root@127.0.0.1:3307/englishbot_offers_test' \

```

Тестовые базы допускаются только локальные с суффиксами `_test` и
`_migration_test`. Проверка миграций восстанавливает пропуски в истории и
проверяет сохранность данных. Браузерные проверки используют реальные
React-экраны и контролируемые ответы API; внешние оплаты не выполняются.
