# Предложения подписки и причины отказа

## Сценарий

При первом входе после окончания бесплатного пробного периода показываем
предложение скидки **20% — SALE20**. Оно также доступно существующим
бесплатным ученикам; при отключённом welcome-триале нужна хотя бы одна
сессия с записанным временем практики.

- «Перейти к тарифам» открывает существующий экран оплаты с применённым SALE20.
- «Спасибо, не надо» открывает вопрос с восемью фиксированными причинами.
- Выбор причины сохраняет ответ и открывает благодарность со скидкой
  **50% — OLD50**. Кнопка тарифов применяет OLD50 вместо SALE20.
- «Другое» — готовый вариант ответа. Ввода своего текста нет.
- Любой этап можно закрыть. После сохранённого ответа опрос больше не
  появляется; после закрытия без ответа новый показ возможен через 24 часа.
- Повторная проверка происходит при новом входе и возвращении приложения
  на передний план. Во время непрерывной работы таймер не открывает окна.
- OLD50 остаётся выбранным для последующего открытия тарифов из профиля
  в этом же сеансе. После нового входа код можно ввести вручную.

Опрос и предложения не показываются действующим подписчикам, ученикам
с действующим доступом школы, пользователям с активным welcome-триалом,
заблокированным аккаунтам и во время `FREE_PERIOD=true`. Пользователи с
историей успешной или возвращённой личной оплаты тоже исключены: это
кампания для ещё не оплативших сервис. Не рекламируются отключённые,
использованные или изменённые по размеру скидки промокоды.

Обе скидки действуют на первую оплату любого доступного тарифа, включая
пробную неделю, месяц, год и два года. Действуют существующие правила
«один раз на аккаунт» и правила продления; скидки не складываются.

## Ответы и аналитика

Фиксированные ответы:

1. Для меня дорого.
2. Не хватает времени заниматься.
3. Пока не понял(а), подходит ли мне сервис.
4. Мне хватает бесплатных возможностей.
5. Не хватает нужных функций или материалов.
6. Возникли технические проблемы.
7. Не получается оплатить.
8. Другое.

В админке — вкладка **«Опрос подписки»**. Периоды: 7, 30, 90 и 365 дней.
Показываются уникальные пользователи и показы, переходы к тарифам,
ответы, закрытия, причины отказа, динамика по дням и последние 100 ответов.
Переходы и оплаты SALE20 и OLD50 показаны отдельно.

Показ считается при выдаче окна сервером. Это не подтверждение просмотра
каждой страницы браузером. Действия относятся к окнам, выданным за выбранный
период; дни считаются по московскому времени. Оплата учитывается только
при успешном статусе и создании платежа после соответствующего показа.
Использование такого же промокода без предшествующего показа не приписывается
кампании. Эти показатели описывают последовательность действий, а не
доказывают, что окно стало причиной оплаты.

Ограничение показов и ответ хранятся в MySQL на аккаунте. Блокировки
строк защищают от одновременных входов с нескольких устройств; повторная
отправка сохраняет первый ответ. API принимает только перечисленные коды
ответов, без произвольного текста. Административная статистика защищена
существующим `X-Admin-Token`.

## Ручной деплой

GitHub Actions не используются. Работать в checkout нужного сервиса.
Новые переменные окружения не нужны; миграции 0001–0044 должны уже быть
применены. При пропусках сначала восстановить историю по инструкции
[learning-production-release.md](learning-production-release.md).

Получить код и собрать образы, сохраняя существующее имя Compose-проекта:

```bash
cd /ПУТЬ/К/englishbot
git pull --ff-only origin main
docker compose ls
PROD_PROJECT='ВСТАВЬ_ИМЯ_СУЩЕСТВУЮЩЕГО_COMPOSE_ПРОЕКТА'
docker compose -p "$PROD_PROJECT" build backend miniapp admin
```

После успешной сборки сделать резервную копию и применить SQL напрямую
через MySQL на хосте:

```bash
APP_DB='ВСТАВЬ_ИМЯ_БАЗЫ'
APP_DB_USER='ВСТАВЬ_ПОЛЬЗОВАТЕЛЯ_БАЗЫ'
umask 077
mkdir -p backups
mysqldump --single-transaction --no-tablespaces -u "$APP_DB_USER" -p "$APP_DB" > "backups/before-subscription-offers-$(date +%Y%m%d-%H%M%S).sql"
```

Убедиться, что резервная копия создалась без ошибок. Затем:

```bash
mysql -u "$APP_DB_USER" -p "$APP_DB" < db/migrations/0045_subscription_offers.sql
mysql -u "$APP_DB_USER" -p "$APP_DB" -e "SELECT version FROM schema_version WHERE version=45; SELECT code,discount_percent,active FROM promo_codes WHERE code IN ('SALE20','OLD50');"
```

Ожидаются SALE20 / 20 / 1 и OLD50 / 50 / 1. Миграция сохраняет ранее
сделанные администратором настройки промокодов; если код отключён или
его процент изменён, окна не будут показаны. Проверить эти настройки до
запуска кампании. Повторное выполнение миграции сохраняет ответы и показы.

После успешной миграции:

```bash
docker compose -p "$PROD_PROJECT" up -d backend miniapp admin
docker compose -p "$PROD_PROJECT" ps
docker compose -p "$PROD_PROJECT" logs --tail=80 backend
```

Проверить тестовым аккаунтом с истёкшим welcome-триалом и без личных оплат:
SALE20 → вопрос → ответ → OLD50 → тарифы с ценами −50%. Проверить закрытие
без ответа, повторный вход в тот же день, исчезновение опроса после ответа
и запись в новой вкладке админки. Реальную оплату для этой проверки
создавать не обязательно.

При откате к предыдущему коммиту пересобрать и перезапустить эти же три
сервиса. Новые таблицы можно сохранить: они не меняют прежние права
доступа или историю оплат. Удаление таблиц потеряет ответы и ограничения
повторных показов, поэтому для отката оно не требуется.

## Проверки разработчика

Серверные регрессии используют выделенную локальную MySQL-базу с именем,
оканчивающимся на `_test`. Интеграционные проверки миграций — отдельную
базу `*_migration_test`. Внешние платёжные и AI-вызовы подменяются.

```bash
PYTHONPATH=backend python -m unittest discover -s backend/tests -v
node --test scripts/test_subscription_offers_browser.cjs
```

Браузерные проверки используют локальные приложения на 5173 и 5174,
настоящие React-компоненты и контролируемые ответы API. Переменные
`OFFERS_UI_URL`, `OFFERS_ADMIN_URL`, `CHROMIUM_PATH` позволяют изменить
адреса и браузер; `OFFERS_SCREENSHOT_DIR` сохраняет снимки.
