# Учебная программа

Включается `LEARNING_ENABLED=true`; деплой описан в [learning-deploy.md](learning-deploy.md).
Программа управляет маршрутом и порядком этапов. Учебные режимы и их API общие
для самостоятельной практики и занятий по программе.

Порядок одного урока:

1. **Грамматика:** существующий `GrammarScreen`, рукописная теория из каталога,
   генерация упражнений через `/api/grammar/lesson/exercises`, обычная практика
   `GrammarExercise` и сохранение результата в прогресс грамматических тем.
2. **Работа над ошибками:** тот же `GrammarScreen` в режиме `weak_points`.
   Ошибочные ответы из предыдущего этапа сохраняются в `user_mistakes`, как и
   ошибки из разговоров. Если ошибок нет, сервер разрешает перейти дальше.
3. **Слова:** существующий `SrsScreen`, озвучка через общий `playWord` и
   `/api/tts/word`, переворот карточки, ответы «Знаю / Не знаю», обычный Leitner.
   Слова занятия добавляются в общий словарь; повторные запросы не меняют
   карточку второй раз. При возврате предлагаются оставшиеся слова.
4. **Аудирование:** существующий `ListeningScreen`, генератор подкастов,
   `PodcastPlayer`, `Transcript` с переводом и добавлением слов. При переходе
   к этапу подкаст готовится автоматически, без отдельного экрана настроек
   и кнопки генерации. Сервер выбирает уровень и ситуацию занятия, добавляет
   его слова; A1–A2 получают минутное аудио со скоростью 0.75×, B1 — две
   минуты, B2–C1 — три минуты с обычной скоростью. Личные настройки
   самостоятельного аудирования на урок не влияют. Подкаст сохраняется между
   перезапусками backend, повторное открытие не расходует квоту повторно.
   Переход открывается после окончания воспроизведения. Ошибку подготовки
   можно повторить в том же уроке; выйти из загрузки можно без потери этапа.
5. **Разговор:** существующий `App`, WebSocket `/ws/voice`, голос или чат,
   исправления, перевод слов, озвучка. Перед стартом видны тема, цель,
   примеры вопросов и условие завершения. Микрофон и сессия открываются
   только по кнопке «Начать разговор»; изменение настроек до неё не
   подключается к серверу. Тема остаётся на экране во время диалога.
   Сервер берёт тему, цель, вопросы, словарь и уровень из сохранённого урока,
   начинает с его первого вопроса; при возвращении повторяет последний
   вопрос из истории. Тема и уровень урока в настройках показаны справочно;
   можно изменить режим, длину ответов и исправления. Для перехода нужны
   три ответа и завершение сессии.
6. **Итог:** программа проверяет результаты всех модулей и засчитывает урок.

Курс использует 50 грамматических целей A1–C1 и 20 коммуникативных ситуаций.
После каждых 20 завершённых занятий открывается сохранённая диагностика,
затем следующий цикл. Число циклов не ограничено, включая уровень C1.
Диагностика имеет собственный банк и сохраняется также в `level_tests`.

Уровень занятий A1–C1 можно выбрать самостоятельно в профиле или настройках
программы. `PUT /api/auth/level` обновляет пользователя и следующий не начатый
урок. Начатое занятие, счётчик завершений и история проверок сохраняются.
Ручной выбор сложности не переписывает результаты диагностики.

В самостоятельном разговоре экран подготовки показывает ситуацию выбранного
собеседника. Все пять уровней A1–C1 доступны в настройках: карточки уровней
адаптируются к ширине, собеседники идут в две колонки, прокручивается только
содержимое настроек, кнопки закрытия и сохранения остаются доступны.

Данные маршрута хранятся в четырёх таблицах миграции 0043. Результаты модулей
и их идентификаторы сессий — в JSON `learning_lessons.answers._modules`.
Дополнительная SQL-миграция для переиспользования модулей не нужна.
Уже завершённые занятия предыдущей версии сохраняются. Незавершённое
занятие предыдущей реализации при первом открытии начинает новый маршрут
этапов с грамматики; прежние ответы остаются в `_legacy`.

Начало создаёт родительскую `lesson`-сессию для статуса урока и суточной квоты.
Её `used_seconds` равен нулю: минуты и XP учитывают существующие режимы.
`learning_lessons.used_seconds` при завершении содержит сумму времени
модулей для результата курса. Завершение урока повторно минуты не начисляет.
Грамматика оценивается по сохранённым заданиям и ответам, а не по присланному
клиентом `is_correct`. Для аудирования и разговора факт завершения не
превращается в выдуманный процент точности.

Суточная квота `free_lessons_per_day` проверяется при начале целого урока.
Начатую программу можно продолжить; грамматические и аудиоэтапы не требуют
повторной покупки отдельных дневных попыток. Для разговора действуют
существующие ограничения минут. Самостоятельные режимы сохраняют свои квоты.
Heartbeat приостанавливает забытый урок примерно через 3 минуты.

MyTracker использует существующую очередь: `course_started`, `lesson_started`,
`lesson_completed`, `checkpoint_started`, `checkpoint_completed`, а также
обычные события модулей. Повторное завершение урока не создаёт новое событие.

## Проверки разработки

Базы для тестов должны быть отдельными, локальными, с миграциями 0001–0043.
Из каталога `backend`:

```bash
TEST_DATABASE_URL='mysql+asyncmy://ПОЛЬЗОВАТЕЛЬ@127.0.0.1:3307/englishbot_mytracker_test?charset=utf8mb4' \
MIGRATION_TEST_DATABASE_URL='mysql+asyncmy://ПОЛЬЗОВАТЕЛЬ@127.0.0.1:3307/englishbot_migration_test?charset=utf8mb4' \
python -m unittest discover -s tests -v
```

Внешние AI/STT/TTS/S2S в автоматических тестах подменяются. Интеграционные
проверки проходят 20 занятий через настоящие API грамматики, SRS, подкастов
и обработчик разговора, затем диагностику и переход к уроку 21. Проверяются
владелец, порядок этапов, квоты, повторные запросы, восстановление после
перезапуска, сохранение истории и ручная смена уровня.

Браузерные проверки требуют Playwright, Chromium и Vite с локальным API:

```bash
VITE_API_BASE=http://localhost:8082 npm --prefix miniapp run dev
# Из корня в другом терминале:
CHROMIUM_PATH=/usr/bin/chromium node --test scripts/test_learning_browser.cjs scripts/test_grammar_browser.cjs
node --test scripts/test_grammar_frontend.cjs scripts/test_mytracker_frontend.cjs
```

`LEARNING_SCREENSHOT_DIR=/tmp/course-review` сохраняет снимки каждого этапа
и размеров 320/390/430/768 px. Необязательный `LEARNING_LUCIDE_PATH` подключает
локальную копию используемой приложением UMD-библиотеки Lucide для снимков
с иконками без внешнего CDN.

Те же проверки доступны для production-сборки: собрать с локальным
`VITE_API_BASE`, запустить `npm --prefix miniapp run preview -- --host 127.0.0.1 --port 5175`,
затем задать `LEARNING_UI_URL=http://localhost:5175 LEARNING_APP_ENTRY=1`.
Открывается настоящее приложение с нижней навигацией, а не тестовая оболочка.

```bash
npm --prefix miniapp run build
npm --prefix admin run build
(cd miniapp && npx tsc -p tsconfig.app.json --noEmit)
(cd admin && npx tsc -p tsconfig.app.json --noEmit)
```
