# Обновление программы на готовые учебные модули

Выполнять в checkout тестового сервиса. GitHub Actions не используется.
Тестовая база и пользователь: `englishbot_staging`. Новых SQL-миграций нет;
для этой версии должны быть уже применены 0001–0043.

## Обновление

```bash
git pull --ff-only origin main
docker compose ls
TEST_PROJECT='ВСТАВЬ_ТЕКУЩЕЕ_ИМЯ_ТЕСТОВОГО_COMPOSE_ПРОЕКТА'

mysql -u englishbot_staging -p englishbot_staging -e \
  'SELECT version FROM schema_version WHERE version IN (41,42,43) ORDER BY version;'
```

Проверка должна показать `41`, `42`, `43`. Пароль вводится по запросу.
Если есть старые пропуски, использовать [проверку миграций](learning-deploy.md),
не прогонять все исторические SQL повторно.

В `.env` сохранить `DATABASE_URL` тестовой базы, существующие секреты входа,
тестовые порты и GPU-настройки. Проверить:

```ini
LEARNING_ENABLED=true
VITE_API_BASE=https://ВСТАВЬ_ДОМЕН_ТЕСТОВОГО_API
```

Собрать образы, затем обновить контейнеры:

```bash
docker compose -p "$TEST_PROJECT" build backend miniapp &&
docker compose -p "$TEST_PROJECT" up -d backend miniapp

docker compose -p "$TEST_PROJECT" exec -T backend \
  curl -fsS http://localhost:8000/health
docker compose -p "$TEST_PROJECT" logs --tail=100 backend
```

Дополнительная пересборка админки не требуется. Каталог `./data/learning`
должен оставаться подключён к backend: в нём сохраняется аудио подкастов.
При старом образе frontend обновление страницы не заменяет пересборку.

Для API сохранить существующие маршруты Nginx: WebSocket `/ws/voice`,
`/api/grammar/` с таймаутом 300 секунд, `/api/listening/` — 600 секунд,
`/api/learning/` — 120 секунд. Пример —
[api-english.conf](../docker/nginx/vps-site/api-english.conf).
Если эти настройки уже применены на тесте, менять Nginx не требуется.

## Проверка на тестовом сервисе

1. Открыть урок: должна появиться обычная грамматика с теорией и примерами,
   затем привычные упражнения. После ошибочного ответа следующий этап
   использует «Работу над ошибками». При отсутствии ошибок его можно пропустить.
2. В словах проверить привычные карточки, озвучку и добавление в общий словарь.
3. При переходе к аудированию подкаст должен готовиться автоматически под
   уровень, тему и слова урока. Отдельных настроек и кнопки генерации в уроке
   нет. Проверить обычный плеер, показ текста, перевод по нажатию на слово,
   повторную попытку после ошибки и переход после окончания воспроизведения.
   В самостоятельном режиме «Слушание» ручные настройки сохраняются.
4. В разговоре проверить микрофон, озвучку и исправления; ответить три раза,
   завершить сессию, сохранить итог урока. Проверить также текстовый режим.
5. Выйти после завершённого этапа и вернуться: пройденные этапы сохраняются.
   Незавершённая попытка грамматических упражнений использует обычное
   поведение модуля: при повторном открытии начинается новая попытка.
6. В «Профиль → Уровень занятий» или «Программа → Настройки программы»
   выбрать новый уровень. Следующий не начатый урок должен измениться;
   начатый урок, завершённые занятия и история диагностики сохраняются.

Завершённые уроки предыдущей версии остаются в истории. Незавершённый урок
предыдущей реализации при первом открытии начинает новые этапы с грамматики;
старые ответы сохраняются в базе. Дальше программа использует общие модули.

Автоматические проверки запускают настоящие API и интерфейсы с подменой
внешних AI/STT/TTS/S2S. Живые генерацию и голос проверить на тестовом сервисе
с его GPU-подключениями. Порядок тестов и снимков —
[learning-program.md](learning-program.md).
