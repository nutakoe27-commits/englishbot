# Реферальная система и ссылки для аналитики (миграция 0032)

Две независимые вещи, обе — **только для Telegram-бота**.

---

## 1. «Приведи друга» — реферальные ссылки пользователей

### Как это работает

Пользователь берёт свою ссылку командой **`/invite`** в боте (или кнопкой
«🎁 Пригласить друга» под `/start`). Ссылка вида:

```
https://t.me/<bot>?start=ref_<КОД>
```

Код (`users.ref_code`, 8 символов) выдаётся лениво при первом `/invite` —
у старых пользователей он NULL, пока они не откроют команду.

Когда по ссылке приходит человек:

| Ситуация | Приглашённому | Пригласившему | `referrals.status` |
|---|---|---|---|
| Человек **впервые** запускает бота | +7 дней | +7 дней | `rewarded` |
| Человек **уже зарегистрирован** в боте | — | — | `skipped_existing` |
| Человек уже приходил по чьему-то приглашению | — | — | строка не пишется, статус ответа `already_referred` |
| Перешёл по собственной ссылке | — | — | `self` |

**Ключевое правило (требование продукта):** если получатель ссылки уже
зарегистрирован в боте, бонус не получает **никто** — ни он, ни пригласивший.
Иначе ссылку можно было бы гонять по кругу между своими аккаунтами.

Количество приглашённых **не ограничено** — пригласивший получает 7 дней за
каждого нового человека, дни складываются к текущей подписке.

Пригласившему сразу приходит уведомление в чат: «по твоей ссылке пришёл X,
тебе +7 дней».

### Что считается «уже зарегистрирован»

`users.bot_activated_at IS NOT NULL` **или** `users.subscription_until IS NOT NULL`.
Второе условие закрывает аккаунты, созданные из Mini App без запуска бота, —
у них уже была подписка/триал, это не новый пользователь.

### Гонка с middleware — важно

`_bot_activation_middleware` в боте проставляет `bot_activated_at` на **любом**
апдейте, и делает это fire-and-forget. Если бы он отработал раньше хендлера,
новичок успел бы стать «уже зарегистрированным» и бонус бы сгорел. Поэтому
middleware **пропускает** апдейты вида `/start ref_…` и `/start src_…` —
`bot_activated_at` для них проставляет backend внутри той же транзакции, что
и начисление дней (`Repo._touch_bot_activated`).

Если будете менять middleware — не сломайте `_is_attribution_start()`.

### Идемпотентность

`UNIQUE(referrals.invited_user_id)` — одного человека нельзя «привести» дважды
никакой ссылкой. Вставка идёт через `INSERT IGNORE`; `rowcount == 0` означает
`already_referred`.

### Аудит

Каждое начисление пишется в `payments` с `plan = 'referral'`, `amount_rub = 0`,
`days_granted = 7` и заметкой, кто кого привёл. Видно в админке на вкладке
«Платежи» (фильтр по плану) и в карточке пользователя.

### Настройка количества дней

`.env` backend'а:

```
REFERRAL_DAYS_INVITED=7     # сколько получает приглашённый
REFERRAL_DAYS_REFERRER=7    # сколько получает пригласивший за каждого
```

Меняется без правки кода; тексты в боте подставляют актуальные значения.

## 2. Ссылки для аналитики (создаются в админке)

Метка источника для рекламы. **Бонусов не даёт** — только считает.

```
https://t.me/<bot>?start=src_<КОД>
```

Создаются в админке: **Рефералка → Ссылки для аналитики**. Код — латиница,
цифры, `_` и `-`, до 32 символов (ограничение Telegram на start-payload).

По каждой ссылке считается:

- **Клики** — все переходы, включая повторные (`ad_links.clicks`);
- **Людей** — уникальные пользователи (`ad_link_hits`, UNIQUE по паре
  link+user);
- **Новых** — из них те, кто до перехода не запускал бота;
- **Оплатили** и **Выручка** — по атрибуции `users.source_link_id`: юзер
  навсегда закрепляется за **первой** ссылкой, по которой пришёл, и все его
  последующие успешные платежи считаются на неё.

Ссылку можно выключить (`active = 0`) — переход всё равно засчитается,
пользователь просто увидит обычное приветствие. Удаление стирает ссылку
вместе со всей статистикой переходов (атрибуция в `users.source_link_id`
при этом остаётся висеть на несуществующем id — удаляйте осознанно).

## Что появилось в админ-панели

Новая вкладка **«Рефералка»** с двумя разделами:

1. **Программа «приведи друга»** — сводка (приведено новых, переходов без
   бонуса, доля новых, активных пригласивших, выдано дней, новых за период
   7/30/90 дней), топ пригласивших и лента последних приглашений с исходом
   каждого.
2. **Ссылки для аналитики** — создание, копирование ссылки, вкл/выкл,
   удаление, таблица со статистикой и раскрывающийся список переходов.

В карточке пользователя добавлен блок **«Рефералка»**: сколько привёл, сколько
переходов всего, сколько дней получил, и кнопка копирования его личной ссылки.

На вкладке «Платежи» в фильтр и подписи добавлены планы `referral`, `org`,
`twoyear`.

## Схема БД (0032)

```
users            += ref_code VARCHAR(16) UNIQUE, source_link_id BIGINT
payments.plan    += 'referral'
referrals        (referrer_user_id, invited_user_id UNIQUE, status,
                  days_invited, days_referrer, created_at)
ad_links         (code UNIQUE, title, note, active, clicks, created_at)
ad_link_hits     (link_id, user_id, is_new_user, created_at,
                  UNIQUE(link_id, user_id))
```

## API

Внутренние (бот → backend, заголовок `X-Bot-Secret`, наружу не выставляются):

- `POST /api/internal/referral/join` — обработка `/start ref_<code>`;
- `POST /api/internal/referral/me` — личная ссылка + статистика для `/invite`;
- `POST /api/internal/adlink/hit` — переход по `/start src_<code>`.

Админские (заголовок `X-Admin-Token`):

- `GET  /api/admin/referrals?days=&limit=`
- `GET  /api/admin/users/{id}/referral`
- `GET/POST/DELETE /api/admin/adlinks`, `POST /api/admin/adlinks/{id}/toggle`,
  `GET /api/admin/adlinks/{id}/hits`
